# PV 不确定性下的电池与电网调度

本说明对应 `ecogrid/dispatch.py`、`simulation.py`、`forecast.py`、
`evaluation.py` 及 `data/measured.py`、`study.py` 的当前研究演示。
系统边界沿用 [PROJECT_SCOPE.md](PROJECT_SCOPE.md)。
这是小时平均能量模型，不表示现场控制器或经过实测验证的电站模型。

## 时间、信息和策略

- 单节点，PV、电池、只进口电网；负荷与购电电价是提前已知的确定性输入。
- 功率 kW、能量 kWh、费用 EUR；每步固定为一小时，`t` 标记 `[t,t+1h)`。
- 在 `t` 发出预测，`valid_time=t...t+23h`，`lead_hours=0...23`。
  决策只看到索引严格小于 `t` 的 PV。当前小时 PV 并非决策前观测。
  实测案例还要求观测到达时间不晚于 `t`；名义小时 PV 的可用时间设为区间起点+2h。
- 每小时重算 24 小时，只发出第一小时的电池充/放电请求。所有情景共享
  第一小时充电、放电和充放电模式；绝不执行情景平均调度。
- 未来小时的电池/电网调度可随整条情景变化。这是**未来整路径揭示的两阶段
  规划近似**，不是多阶段最优策略。未来计划每小时都会被丢弃并重算。
- 当前小时的购电、弃光、缺电随实际供需自动平衡。电池请求由同一个负荷优先
  保护规则执行：供电不足先削减充电，电池放电受实际 SOC/功率/负荷限制。
  保护规则是因果的在线安全动作；离线回放用该小时平均 PV 汇总其能量结果，
  **不声称验证了小时内波动下的可行性**。

三种策略只改变预测表示和目标：确定性使用单条点预测；风险中性使用等权
残差情景，λ=0；风险规避使用同一情景、λ>0。压力测试与正常数据不混合。

## 共同物理模型

情景 `s`，小时 `t`，已知负荷 `L_t`、价格 `a_t`，可用 PV `A_st`。
变量：进口 `g_st`、使用的 PV `v_st`、充电 `c_st`、放电 `d_st`、
小时结束电量 `E_st`、未供电负荷 `u_st`，二进制充电模式 `z_st`。

```text
g_st + v_st + d_st + u_st = L_t + c_st
0 <= g_st <= Gmax;  0 <= v_st <= A_st;  0 <= u_st <= L_t
E_st = E_s,t-1 + eta_c c_st - d_st / eta_d
0 <= E_st <= Emax
0 <= c_st <= Pmax z_st;  0 <= d_st <= Pmax (1-z_st)
c_s0 = c_00; d_s0 = d_00; z_s0 = z_00
curtailment_st = A_st - v_st
```

初始电量各策略相同。没有热机、风电、出口、容量优化或随机电价。
`solve_dispatch` 的 `balance/energy/charge_mode/discharge_mode/shared_action`
约束直接对应以上各行，未来每个情景也保留充放电互斥。

## 费用、终端与风险

每条路径的规划损失为：

```text
C_s = sum_t [a_t g_st + k_b(c_st+d_st) + k_u u_st] - v_E(E_s,last - E_initial)
objective = (1-lambda) sum_s p_s C_s + lambda CVaR_alpha(C)
CVaR_alpha(C) = min_eta [eta + sum_s p_s max(C_s-eta,0)/(1-alpha)]
```

随附实验配置的电池为 8 kWh / 3 kW，电网进口上限 2.5 kW，初态 4 kWh，双向效率各
0.95。`k_b=0.01 EUR/kWh` 按充放电吞吐量计价，是简单电池使用成本代理，
不是寿命退化模型。`k_u=10 EUR/kWh` 是固定缺电惩罚。参数在比较前固定，
没有根据测试结果选择它们。

终端不用强制清空或任意补满；剩余电量固定估值 `v_E=0.18 EUR/kWh`。
报告每小时 `inventory_adjustment=-v_E(E_after-E_before)`，全期求和恰好
得到上述终端项。正式报告并列保留四项：

```text
actual_expense_t = price_t * grid_t + k_b * (charge_t + discharge_t)
shortage_penalty_t = k_u * ENS_t
inventory_adjustment_t = -v_E * (E_after - E_before)
adjusted_loss_t = actual_expense_t + shortage_penalty_t + inventory_adjustment_t
```

`actual_expense` 指实际执行产生的基础费用，含电池使用成本代理，不能解释为
全部真实账单；缺电惩罚与库存估值另列。兼容旧表的 `operating_cost` 仍包含
缺电惩罚，`loss` 等于调整后损失。某些充电小时的库存调整及 loss 可以为负。

每个优化结果的场景成本重新计算风险，不把求解器 `eta` 当作报告 VaR。
`finance.value_at_risk` 统一使用下分位数 `inf{x:F(x)>=alpha}`；
`finance.cvar` 按最差 `1-alpha` 概率质量加权，包含分位点处的部分质量。
默认概率与显式等权口径相同；空值、非有限值、负概率及未归一化概率被拒绝。
λ=0 时不需要 CVaR 辅助变量。离散最优 eta 可以不唯一，这不会改变报告口径。

λ=1 的目标只约束尾部，非尾部追索成本可能因最优解不唯一而不同。
`solve_dispatch(tail_tiebreak=True)` 因而先求最小 CVaR，再约束
`CVaR <= primary_CVaR + 1e-7 EUR`，第二次最小化期望路径损失。
这不是隐藏的 epsilon 加权目标。两次均验证解；最终独立复算的 CVaR 不得超过
该界再加配置的 1e-6 可行性容差。λ<1 不加第二次求解。
可用 `tail_tiebreak=False` 做原始纯 CVaR 对照，第一遍及第二遍诊断均写入账本。

## 真实执行与完美预知参考

`simulation.execute_hour` 接收决策时发出的请求，实际充电不超过：

```text
min(requested_charge, Pmax, (Emax-E)/eta_c, max(actual_PV+Gmax-load,0))
```

放电不超过请求、功率上限、`E*eta_d` 和负荷；PV 优先供给净需求，随后
购电，剩余负荷记为 ENS。SOC 只用实际充/放电重新计算，没有 SOC clip。
能量导出的功率上界向浮点可行域内移动，并核对严格状态边界，必要时再缩小几个 ULP，避免电量越过浮点边界；
这改变的是实际功率，能量账本仍保持一致。保护削减量单独记录。

有限情景无法覆盖所有天气；保护动作也说明实际策略不等于规划中的任一未来
情景路径。预测风险只作为规划诊断，正式比较使用执行后的损失。

`evaluation.perfect_foresight` 对**完整评估期**实际 PV 求解一次，使用相同
物理约束、初态、费用和终端估值，并逐小时通过同一执行函数验证轨迹。
只有全期损失定义一致且通过核对，才报告 `regret=policy_loss-perfect_loss`。
滚动策略可使用评估终点之后已知的负荷/价格及其预测，但只对评估期记账；
完整评估期的完美预知解仍是同一期可行轨迹的下界。每日表仅做分组记账，
不把有跨日电量转移的单日成本差标成单日最优 regret。

完美预知仅给出同完整评估期、同损失定义的**总调整后损失下界**。
它没有分别最小化小时/日 CVaR、ENS、购电量或实际费用，因此不是这些指标的普遍下界。

### 单独的执行规则敏感性

默认 `execute_hour(execution_rule="planned")` 保留以上只削减请求的规则。
可选 `execution_rule="deficit_discharge"` 在执行充电已为零时，将实际总放电提升至：

```text
D = max(load - actual_PV - Gmax, 0)
d_actual = max(d_original_execution, min(D, Pmax, E_before * eta_d))
emergency_discharge = max(d_actual - requested_discharge, 0)
```

充电请求若因供给不足被取消，可以转为追加放电；任一实际小时仍充放电互斥。
使用原来的浮点功率边界、SOC守恒与分项费用。原请求不改写；削减量保持非负，
追加量单独记账。`run_policy` 把新实际 SOC 送入下一小时优化，完整重跑后续时段，
不是在旧账本上单独减去缺电。购电、使用成本、库存项和后续可用电量都会受影响。

这是小时平均供需层面的控制规则反事实，**没有验证实时测量或小时内控制**；
允许观测后改变动作也不是原优化器已建模的最优应急追索。优化目标、共享请求及
未来整路径追索近似保持不变。确定性、风险中性、CVaR和完美预知回放统一使用
同一选择。控制对照只用原预选冬/夏首48h、sampled-12；与all_matching实验分开。
48h完美预知重新优化完整48h，不能拿原七天完美预知的前48h当其最优参考。

## 正式实测案例：直接使用原始电表

正式案例来自 [OPSD Household Data 2020-04-15](https://data.open-power-system-data.org/household_data/2020-04-15/)，
CoSSMic 的 `DE_KN_residential6_pv`。归属：Open Power System Data (2020)，
CoSSMic / ISC Konstanz，CC BY 4.0。

先检查官方小时 CSV、README、元数据与处理代码。小时 CSV **仍为累计 kWh**，
通过 `resample('60min').last()` 聚合；其插补标记并不能揭示全部处理：短间隔
重采样和全序列异常清理还有未来数据依赖。因此正式实验不把该发布版用于训练、
校准或实际 PV，而是从官方原始 ZIP 中按字节范围提取约 3 MB 压缩成员
`original_data/DE_KN_residential_006/phptimeseries/feed_43.MYD`。
[官方解码代码](https://github.com/isc-konstanz/household_data/blob/2020-04-15/household/read.py)
定义 9 字节 `<xIf`：占位、Unix UTC 秒、float32 累计 kWh；没有额外 DST 转换。
缓存核对 ZIP CRC32、解压长度及固定 SHA256，不下载整包，不覆盖已有缓存。

`data.measured.load_opsd_original_pv` 读取原始记录；`build_measured_frame` 令
`r(t)` 为不晚于小时边界 `t` 的最后一个真实读数时间：

```text
energy_t = 0.5 * [meter_kWh(r(t+1h)) - meter_kWh(r(t))]
available_PV_t = energy_t / 1h                 # kW, nominal [t,t+1h)
```

只差分一次；没有插值、补行后填值、全序列统计滤波或按测试最大值归一化。
0.5 是事先声明的固定功率缩放，5 kW 是仿真情景上界，均不是已核实的电站铭牌。
保留所有小时，拒绝缺测、负差分、超界或两端电表读数超过 180 秒陈旧的窗口。
四个窗口实际最大端点滞后分别为 103/78/160/104 秒。真实计量跨度为
3490–3665 秒，其电量分配给名义一小时；保留真实端点和跨度，明确这是边界对齐近似。

历史通信到达时刻未知，统一假定名义小时 `t` 的 PV 数据在 `t+2h` 才可用于预测。
`PVForecaster.predict` 同时要求 `index < issue` 与 `observation_available_at <= issue`。
拟合只用校准起点前已可用的训练观测；残差窗口的所有真实值也须在冻结时刻已可用。
因此每段有 1439 个可用于首次拟合的训练小时、696 个可冻结的 24h 残差块。
电池 SOC 另假定可直接测得；实际执行依然用统一的小时供需保护规则。

这是**原始实测发电驱动的仿真**：观测发电充当可用 PV，没有识别历史限电、
停机与潜在辐照能力，也没有验证现场控制器或历史通信延迟。负荷、电价、电池和
电网容量均为外生实验设定。

## 数据、预测和概率

`data/benchmark.py` 提供固定种子的合成日照/云量曲线及公开历史天气案例。
公开数据来自 [Open-Meteo 历史天气 API](https://open-meteo.com/en/docs/historical-weather-api)，
慕尼黑 2024-05-01 至 2024-08-08，GMT。辐射为前一小时平均 W/m²，API 时间
标签减一小时转为区间起点；响应单位、连续性、重复时间、有限值均检查。
PV 代理为 `clip(5 kW * radiation/1000 * 0.8, 0, 5 kW)`。
这是历史天气估算，不是实测电站 PV，也不是当时发布的天气预报。负荷与电价
是公开声明的确定性演示假设，不来自电表/市场历史数据。数据提供者：Open-Meteo
及其上游再分析资料；[数据许可与署名说明](https://open-meteo.com/en/terms)。

原始响应存在 `data/raw/`，不同查询不能覆盖或复用不匹配缓存；转换数据在
`data/derived/`。物理容量投影是显式模型变换，原始响应不被修改。

以首个完整 UTC 日为起点：60 天训练、接着 30 天校准、然后测试。
预测是“50% 训练期相同时刻均值 + 50% 决策前七天相同时刻均值”；后半项随
已经发生的观测更新。不存在使用当前小时实际 PV 的捷径。
校准按历史每小时重做该预测，保存完整 24 小时预测误差向量；所有有效时刻
必须在校准结束之前。预测期从相同 UTC 发报小时的历史误差向量中整块抽样，
保留块内误差时序相关性，再投影到 `[0,PV_capacity]`。投影改变分布，情景
是经验近似，并不声称是真实概率模型。库在测试前冻结，不用测试期误差更新。
不同风险权重共享同一时刻的抽样种子和情景。

`ResidualLibrary.sample_scenarios(mode="sampled")` 保留12条有放回等权抽样。
`mode="all_matching"` 则使用冻结库中所有同 UTC 起报小时的来源，每个来源一次，
候选数按 `origins.hour` 实际计算。重复或截断后相同的整条路径仍保留为多个来源行，
每行概率 `1/N`，不去重，因此完全保留经验概率质量。若未来合并，必须累加原权重。
α=0.9 时优化尾部等效来源数为 `0.1N`；12条抽样为1.2，绝不是12个独立尾部事件。
全部候选仍来自同一个有限校准库，不增加历史信息或独立实测天数。

### 有限成员和并列值诊断

`diagnostics.ensemble_diagnostics` 报告原精确端点下的含边界覆盖、严格越界、
边界并列及秩区间，不扩大情景区间。仅在连续、可交换参照中：

```text
P(actual < min ensemble) = 1/(N+1)
P(q_lower(0.1) <= actual <= q_lower(0.9))
  = [ceil(0.9N) - ceil(0.1N)] / (N+1)
```

N=12 对应1/13和9/13，不是零与80%。33/393次低于下界或67.43%区间覆盖
本身都不能证明失准或校准成功。残差块来自历史、抽样有放回、输出被容量截断，
并有并列、时序相关与日间筛选；真实情景不自动满足这个理想参照。

以1e-9 kW仅识别并列和严格排除，令 `l=#(member<actual-tol)`、
`e=#(|member-actual|<=tol)`，观测秩可能范围为 `[l+1,l+e+1]`；
秩单元归一化区间为 `[l/(N+1),(l+e+1)/(N+1)]`。报告区间宽度与并列比例，
中点是确定性描述，不视为随机化 PIT，也不据此做均匀性或显著性结论。
零发电使夜间含边界覆盖容易达到100%，因此同时报告全小时与原定义的日间代理。

## 评估与压力测试

`configs/mechanisms.json` 是查看原结果之后确定的收尾敏感性配置，不是新独立验证。
原 `results/study/` 与 `docs/results/` 中的原始表保持原字节；新结果在独立目录。
28天对照只改变sampled-12/all_matching；冬夏首48h对照只改变执行规则。
`run_mechanism_study` 核对原数据、设置、输入及逐行执行后复用未受影响的基线，
重放sampled-12并核对原动作、SOC与损失，再运行all_matching及追加放电。
不会重新运行原容量、种子和压力扫描。复用记录的本轮求解时间为0，原求解时间
另存 `original_solve_seconds`，不能把0解释为算法免费。原28天风险统计保持不变。

本次运行实际为每个起报小时29个合格来源，优化尾部等效数由1.2变为2.9。
完整结果没有显示CVaR额外收益；追加放电仅降低冬季确定性策略的全期缺电，
夏季会将部分缺口移至后续小时。数值、有限成员诊断及分项成本见
[README收尾结果](../README.md#收尾敏感性情景与执行机制) 与
[正式汇总](results/mechanisms/mechanism_summary.csv)。这是同一批数据上的事后机制解释，
没有增加独立评估日或冻结新策略排名。

正式配置为 `configs/measured.json`，在任何策略求解前保存 `protocol.json`：
2017-01-01、04-01、07-01、10-01 UTC 起各七天，合计 28 个不同日历日。
每段只使用此前 60 天训练、30 天校准；测试窗口互不重叠，较晚窗口的历史可包含
已经发生的早期评估日期，属于顺时间推进，而不是四个独立试验。
`select_measured_windows` 逐段验证质量，失败时不依据效果搜索替代日期。

主比较固定确定性、风险中性、λ=0.5 及各七天完整期完美预知；α=0.9，12 情景，
种子 42。冬、夏两个代表窗口在看效果前固定为解释对象：首 24h 用种子 7/99 复跑、
购电上限 2.0/3.0 kW 对照，以及 λ=1 原始/平局处理对照；首 48h 单独做低 PV/
偏高预测压力。除压力外各组原始 PV 不变；这些是单因素小实验，不进行全组合扫描。
不同种子与压力数据不并入主比较的 28 天样本，图中的代表轨迹固定取冬/夏首 48h。

`daily_metrics` 与 `nonoverlapping_24h_metrics` 分别按 UTC 日及评估起点聚合：

```text
L_block = sum_24h L_t; ENS_block = sum_24h ENS_t
CVaR = worst (1-alpha) probability mass of the chosen realized sample population
```

所有本轮窗口从午夜开始，完整 UTC 日与非重叠 24h 块因此相同，但两种表都保存。
部分块保留且标记，在风险统计中排除并报告数量；缺小时不能通过压缩日历组成一天。
小时表样本为 1h 损失/能量，日块表为 24h 总损失/能量；VaR/CVaR 的货币值是
对应样本的 EUR，小时均值可表达为 EUR/h，日均值可表达为 EUR/day，日 ENS 为 kWh/day。
不把日总量除以 24 后冒称日尾部，也不平均各窗口 CVaR 代替合并样本的 CVaR。

滚动规划 CVaR 是**某次起报时的条件情景 24h 总损失**；小时风险与日块风险是
**策略连续执行后的经验分布**。日块经历 24 次预测更新和决策，未执行任一完整
规划场景路径；即便同为 24h 量，两者的分布、信息集和动作也不同。
主比较每策略有 672 小时、28 日：90% 尾部只有 67.2 等效小时或 **2.8 等效日**。
不能据此宣称统计充分性；一日/两日敏感性对照的尾部更小，仅作为机制例证。

`risk_summary_samples` / `risk_summary_blocks` 对基础费用、缺电惩罚、库存项、
调整后损失与 ENS 分别报告风险。`diagnostics.tail_contributions` 另在同一个
调整后损失尾部中分解成本；它们可相加还原该尾部均值，**各成本独立 CVaR 则不可相加**。
`compare_actions` 按同日期/电网/种子配对请求和执行，报告保护规则消除动作差异的小时。
预测诊断按起报时刻与 lead 保存；日间代理事先定义为点预测或实际 PV 大于 1e-7。
诊断在执行之后读取真实值，不回流到决策。不同 lead 的覆盖率不当成独立样本。

下述合成与天气配置继续作为可离线运行的基础演示，正式实测结果不与其混合。

快速配置：测试 48 小时，12 情景；较长配置：168 小时，24 情景。
λ 使用 0、0.5、1；λ=0 即风险中性。压力例持续 48/72 小时，把实际 PV
乘 0.2，并在正值点预测上固定增加 0.75 kW（不超过装机），保留原训练和残差库。
后续预测可使用已经观测到的压力期历史；不能使用压力期未来。

报告平均每小时 loss、每小时 VaR/CVaR、全期 ENS、进口、弃光、吞吐量，
并分开报告三个成本及库存项。LOLP 是样本中 ENS>1e-7 的小时比例；
EENS 是该样本平均每小时未供电能量（kWh/小时），不是多条独立年度轨迹的期望。
尾部使用实际执行小时的等权经验分布，**不是优化内部情景概率**。
α=0.9 时 48 小时只有 4.8 个等效尾部小时，168 小时只有 16.8 个；小时之间
有相关性，均不用于宣称统计显著性。每日总量另存，不混用小时和日尾部。

求解时间为每次构模、求解和验证的墙钟时间；数据获取、预测和绘图不计入。
只接受 HiGHS optimal 且残差不超过 1e-6 的解；时间上限/不可行/残差失败
使运行显式失败并写入 manifest，不能用零动作假冒成功。
Manifest 保存有效配置、种子、源数据/源码哈希、库版本、划分日期和求解设置。

## 手算例与代码对应

一小时：负荷 2 kW、PV=0、空电池、进口上限 1 kW、价格 0.30 EUR/kWh。
最优进口 1 kWh、缺电 1 kWh、充放电 0，SOC 不变：

```text
购电 = 0.30; 电池使用 = 0; 缺电惩罚 = 10; 库存调整 = 0
loss = 10.30 EUR
```

对应 `tests/test_dispatch.py::test_hand_solved_shortage_and_terminal_inventory_value`。
如果负荷改为 1、错误预测导致请求充电 3，实际仍无 PV，电网全部供负荷，
实际充电必须为 0，SOC 不能增加；对应 `test_one_hour_accounting_and_no_unpowered_charging`。
风险手算：损失 `[0,100]` 等权、α=0.25，VaR=0，最差 75% 的 CVaR
为 `(0.25*0+0.5*100)/0.75=66.6667`，与是否显式传入等权概率无关。

追加放电手算：SOC=1 kWh、放电效率0.8、功率上限2 kW、负荷2 kW、PV=0、
电网1 kW，原充放电请求均为0。原规则缺电1 kWh；新规则追加放电0.8 kWh，
SOC降到0、缺电0.2 kWh。价格0.2、其余默认成本下，损失为
`0.2 + 0.01×0.8 + 10×0.2 + 0.18 = 2.388 EUR`。
下一小时必须从空电池重新规划，不能继续沿用原SOC；回归检查覆盖这一状态传递。

纯 CVaR 平局小例：三小时负荷 `[1,2,1]`，价格 `[0.2,0.4,0.1]`，两个等权
PV 路径 `[0,0,0]`、`[2,2,2]`，α=0.5；电池 2kWh/1kW、初态 1kWh、
进口上限 1kW、效率 1、吞吐成本 0.01、终端值 0。低 PV 路径损失为
`0.2 + 0.4 + 0.01 + 0.1 = 0.71`。本机原始解让高 PV 路径额外消耗 0.01，
二次求解将其降为 0：期望损失 0.360→0.355，CVaR 仍为 0.71，第一步动作相同。
这证明非尾部自由度存在，不能据此声称实际运行收益改善。

## 中文讲解与常见追问

**问题→预测→情景→优化→执行→评价：** 电网有限时，电池需要在不确定的明天
保留多少能量？先用已可用的历史 PV 构造简单点预测，再整块抽取过去 24h 误差，
让规划看到连续阴天等误差形态；三策略在同一个物理模型中权衡成本与缺电损失。
当前电池请求必须跨情景相同，实际供电出现后由统一保护规则执行并更新 SOC。
最后只用真实执行账本计算费用、可靠性与小时/日风险，比较收益是否足以解释额外成本。

- **为何 CVaR 不一定更好？** 有限情景可能漏掉不利误差；规划目标和事后评价分布
  不同；风险中性策略也可能已提供足够储备。零额外收益是有效结果。
- **为何不直接执行情景平均动作？** 平均状态/动作不自动满足互斥和状态演化，
  当前请求必须由共享决策给出，后续轨迹只是近似追索。
- **为什么算完美预知？** 检查相同约束与完整期成本的可比下界；它不证明某种策略
  的日 CVaR 或 ENS 不可能更低。
- **数据是否真实？** 电表记录是真实测量；功率缩放、小时对齐、可用 PV 解释、
  信息延迟、负荷/价格和资产配置均是明示的仿真假设，不是部署验证。
- **28 天够不够？** 足够展示管线与机制，不足以证明长期优势或尾部显著性；
  90% 日尾部只有 2.8 个等效观测，多种子也不能变成更多真实天气日。
